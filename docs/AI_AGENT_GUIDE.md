# AI Agent로 기능 추가하기

행복한 옥키 프로젝트 폴더를 에이전트의 작업 폴더로 열고 [AGENTS.md](../AGENTS.md)를 작업 맥락으로 사용합니다. Claude Code는 루트의 `CLAUDE.md`에서 같은 파일을 불러옵니다. [Claude Code의 파일 불러오기 문서](https://code.claude.com/docs/en/memory#import-additional-files)

## 1. 화면에서 확인할 동작부터 요청하기

어디서 기능을 실행하는지, 실행하면 화면에서 무엇이 바뀌는지, 취소하거나 다시 실행하면 어떻게 되는지를 적습니다. 저장해야 할 설정인지도 명시합니다. 모션이 필요한 경우에는 참고 이미지와 함께 시작 자세, 움직일 부위, 끝 자세를 설명하면 구현 결과를 비교하기 쉽습니다.

아래는 아직 구현되지 않은 기능을 요청하는 예시입니다.

```text
행복한 옥키에 산책 일시 정지를 추가해줘. 프로젝트의 AGENTS.md를 읽고 시작해줘.

- 옥키와 알림 영역의 우클릭 메뉴에 '산책 일시 정지'를 넣어줘.
- 선택하면 현재 위치에서 자연스럽게 멈춰 앉고 메뉴 문구가 '산책 재개'로 바뀌어야 해.
- 공을 물고 돌아오는 도중이면 공을 내려놓은 뒤 멈춰줘. 잠들기, 드래그, 밥 주기는 계속 사용할 수 있어야 해.
- 산책 재개를 선택하면 자율 행동으로 돌아가고, 앱을 다시 열면 기본값인 산책 가능 상태로 시작해줘.
- Windows에서 일시 정지와 재개, 공을 가져오는 중 일시 정지를 확인하고 실행한 테스트를 알려줘.
```

## 2. 현재 흐름에서 변경할 곳 찾기

| 바꾸려는 기능 | 먼저 볼 곳 |
| --- | --- |
| 상태창 버튼이나 이름 편집 | `src/panel.rs`의 입력과 `src/native.rs`의 `Command` 처리 |
| 자율 행동이나 수면 | `src/behavior.rs`의 행동 선택, `src/game.rs`의 상태 전환, `src/native.rs`의 표시 |
| 방향 전환이나 새 애니메이션 | `assets/`와 `src/render.rs`의 프레임 구성, `src/native.rs`의 `behavior_pose` 또는 `turn_pose` |
| 저장 옵션 | `src/game.rs`의 `SavedPet`, `src/native.rs`의 저장 작업 |

에이전트가 변경할 흐름을 찾으면 실제 실행 진입점까지 연결하도록 요청합니다. 예를 들어 버튼 추가에는 클릭 입력, 상태 반영, 표시 갱신이 함께 필요합니다.

## 3. 검증하기

PowerShell에서 `cargo fmt --check`, `cargo test --locked`를 실행합니다. 창 동작과 입력을 바꿨다면 기존 인스턴스를 종료하고 아래 테스트도 실행합니다.

```powershell
cargo test --release --locked --test windows_lifecycle -- --ignored --nocapture
```

애니메이션은 자동 테스트와 별도로 새 실행 파일을 열어 시작과 끝을 확인합니다. 중간에 마우스로 끌거나 다른 행동을 시작해도 자연스럽게 돌아오는지 살핍니다. 이름이나 설정처럼 저장이 필요한 기능은 앱을 종료하고 다시 열어 확인합니다.

## 4. 결과 확인하기

에이전트에게 바뀐 파일, 사용 방법, 실행한 테스트와 결과를 요청합니다. 검증 중 놓친 조건이 보이면 “공을 물고 돌아올 때 일시 정지를 눌렀더니 공을 내려놓기 전에 멈췄어”처럼 실행 순서와 실제 화면을 알려주면 수정 범위를 좁힐 수 있습니다.
